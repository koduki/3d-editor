# ADR-0001: v0.4.0 外部サーバー構成を廃止し、単体完結 APK（Minimal Reboot）へピボットする

- **ステータス:** Accepted
- **日付:** 2026-11-22

## 背景（Context）

v0.4.0（XR-ACP Workbench）では、別ホストまたは Termux 上で外部 Node.js ブリッジサーバーを起動し、Android 側からカスタム Web IDE（独自チャット UI・Diff 承認 UI・音声入力・接続プロファイル管理・セッション履歴 DB 等）を接続する構成を採っていた。

しかし Android XR（XREAL AURA 等）に **物理キーボード＋マウス／トラックパッド** を接続して日常的にコードを書く用途に照らすと、以下の課題が顕在化した：

1. **導入障壁の高さ**：Termux や外部サーバーの別途インストール・設定・起動が必要で、APK インストールだけですぐ開発を始められない。
2. **過剰設計と保守コスト**：約 14,000 行におよぶ独自エディタ／エージェント UI がコア体験（「ファイルを開く・編集する・保存する・CLI を叩く」）よりも重くなっていた。
3. **スマホ前提 UI とのミスマッチ**：物理キーボード＋マウス前提の空間デスクトップでは、タッチ補助ボタンや独自チャット枠よりも標準的なデスクトップ級エディタ（VS Code Web）の方が圧倒的に使いやすい。

## 決定事項（Decision）

- v0.4.0 構成は Git タグ `v0.4.0` としてアーカイブし、`main` から外部 Node.js サーバー・独自 ACP/Web IDE 実装を削除する。
- v0.5.0 以降は **「APK 1 本をインストールするだけで完結する、最小構成の Android XR 向けコードエディタ＋内蔵 POSIX CLI 環境」** にスコープを絞る：
  1. エディタサーバー（`openvscode-server`）と最小 Linux 環境の完全内蔵・自動起動
  2. 基礎的なエディタ操作（開く・閉じる・編集・保存）と XR 光学視認性の最適化
  3. Android XR ↔ POSIX の双方向ファイル共有
  4. 最低限の内蔵ターミナルとパッケージ管理（`apt`, `git`, `gh` 等）

## 検討した代替案（Alternatives Considered）

- **代替案 A：v0.4.0 の外部 Node.js + カスタム Web IDE を拡張し続ける**
  - 導入手順が複雑なままであり、エディタ自体の品質で VS Code（Monaco）に追いつくコストが見合わないため不採用。
- **代替案 B：Termux + ブラウザ（TWA）連携を前提にする**
  - ユーザーに Termux の導入・設定・バックグラウンド常駐管理を強いることになり、「APK 1 本で完結」という体験に反するため不採用。

## 影響とトレードオフ（Consequences）

- **メリット**：コードベースが Kotlin 約 11 ファイル＋最小 HTML に収まり、保守性・起動の確実性・エディタ品質が大幅に向上した。
- **トレードオフ**：APK サイズが約 109 MiB（ランタイム同梱分）になる。また独自 AI チャット UI 等は削ぎ落としたため、AI 支援は将来的に POSIX ターミナル上の CLI ツール（`gh` / エージェント CLI 等）として導入する方針とした。
